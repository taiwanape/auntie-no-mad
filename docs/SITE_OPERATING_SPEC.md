# 阿姨別生氣網站營運規格

本文件整理目前已確認的網站方向、每日更新邏輯與品質底線。之後調整自動化或內容時，先以這份規格與 `docs/VOICE_GUIDE.md` 為準。

## 產品定位

阿姨別生氣是一個台灣生活情報內容網站。語氣要像阿姨提醒晚輩：白話、碎念、有一點犀利，但不要惡毒，不要像新聞機器人，也不要亂講沒有來源的事。

網站主要區塊：

- 生活雷達：台灣生活新聞、民生資訊、交通、天氣、消費事件。
- 踩坑日記：詐騙、消費糾紛、社群陷阱、旅遊與交通踩坑提醒。
- 股市 ETF：每天 4 個觀察項目，只做教育與資訊整理，不做投資建議。
- 工具箱：單位換算等小工具，之後可以繼續加。
- 好物推薦：保留可擴充位置。
- 舊文章：保留歷史內容入口，不堆在首頁底部。
- 冰箱便條紙：每天一句短提醒。

## 每日更新時間

GitHub Actions workflow：`.github/workflows/daily-update.yml`

- 04:00 Asia/Taipei：主更新。
- 06:00 Asia/Taipei：備援更新，避免 GitHub 排程延遲或漏跑。
- 目標：每天 07:00 前首頁、文章頁、RSS、JSON Feed、sitemap 都已經更新。
- 手動 `workflow_dispatch` 預設只做 dry-run；只有排程或手動指定 `publish=true` 才會寫入正式首頁。

## 每日更新內容

每日更新腳本：`scripts/daily-update.mjs`

每日產生：

- 生活雷達 2 則。
- 踩坑日記 2 則。
- 股市 ETF 4 則：熱門股 A、熱門股 B、新星觀察股、風險題材或高人氣 ETF。
- 冰箱便條紙 1 句。
- 舊資料保留到 `archive`。

股市內容禁止：

- 不寫買進、賣出、目標價、保證獲利。
- 不用報明牌語氣。
- 必須附來源與風險提醒。
- 資料不足時寧可不更新該項，不硬掰。

## 資料來源

優先使用免費公開來源：

- 中央社 RSS：生活、社會、財經。
- 臺灣證券交易所公開資料。

所有自動內容都必須保留 `sourceUrl`。如果來源抓取失敗，保留舊資料，不讓首頁壞掉。

## 圖片品質規格

圖片是本網站的核心品質線，不可再出現低品質拼貼。

允許：

- OpenAI Images 產生的完整 AI 圖文插畫。
- 已人工審核通過的高品質 AI 圖庫。

禁止：

- 臨時 SVG 拼貼圖。
- 線條 icon 或幼稚園風格色塊。
- 假中文、亂字、水印、奇怪招牌。
- 圖片與內文完全無關。

固定風格：

- 亮黃底、半色調、粗黑線、白色貼紙邊。
- Q 版阿姨角色：捲髮、pixel 墨鏡、金耳環、豹紋上衣、黑色圍裙。
- 詐騙與踩坑圖可以有少量清楚文字，例如「不要匯款」、「先查證」，但不能有亂字。

如果 OpenAI 圖片 API 失敗：

- 不停止文字資料更新。
- 改用已審核的高品質 AI 圖庫。
- 絕對不回退到 SVG 或低品質 icon 圖。
- 原因寫入 `data/review-report.json`。

## 舊資料保留

- 正式資料在 `data/site-content.json`。
- 歷史資料保留於 `archive`。
- 文章 HTML 不刪除，讓舊連結可繼續打開。
- 自動更新失敗時，保留上一版正式內容。

## 部署

部署使用 GitHub Pages，並在每日更新 workflow 內完成：

1. 產生資料與文章頁。
2. 產生 SEO 檔案。
3. 執行內容驗證。
4. 自動 commit / push。
5. 上傳 Pages artifact。
6. 部署到 GitHub Pages。

這樣可以避免 bot commit 後 Pages 沒有重新部署。

## 每日 QA

早上檢查時至少確認：

- `data/site-content.json` 的 `site.updatedAt` 是否為當日。
- 首頁是否出現當日生活雷達與踩坑日記。
- 股市 ETF 是否有 4 個項目。
- 圖片是否為 `.jpg` 或 `.png`，不應出現 `.svg`。
- `Daily Auntie Update` workflow 是否成功。
- GitHub Pages deploy 是否成功。
